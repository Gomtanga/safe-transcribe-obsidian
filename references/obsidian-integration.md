# Obsidian 통합

## 편집 전 확인

1. vault 루트와 정확한 대상 노트 경로를 확인한다.
2. 대상 파일이 vault 안에 있는지 확인한다.
3. 기존 frontmatter, 제목 구조, 위키링크, 임베드, callout, HTML, 코드 펜스, 수기 메모를 읽는다.
4. 기존 노트를 작업 디렉터리의 `backup/`에 복사한다. vault 안에 불필요한 백업 노트를 만들지 않는다.
5. Git 저장소라면 현재 변경 상태를 확인하고 사용자 변경과 겹치는 부분을 보존한다.

## 대분류 우선 원칙

세부 문장을 위에서부터 옮기기 전에 전체 검토본을 읽어 분류 지도를 먼저 만든다. 다음 표를 임시 작업물로 사용한다.

| 대분류 | 포함할 개념 | 실습 및 명령 | 질문 및 오해 | 근거 녹음 | 불확실성 |
|---|---|---|---|---|---|

분류 기준:

- 수업의 실제 전개 순서보다 학습자가 다시 찾기 쉬운 개념 구조를 우선한다.
- 대분류는 서로 겹치지 않게 만들고, 반복된 설명은 가장 적절한 한 곳에 통합한다.
- 하나의 내용이 여러 범주와 관련되면 본문은 한 곳에 두고 위키링크나 짧은 교차 참조를 사용한다.
- 실습 명령은 설명과 분리하되, 어떤 전제와 결과를 가졌는지 함께 기록한다.
- 학생 질문은 질문 의도, 강사 답변, 추가 설명, 남은 불확실성으로 나눈다.

## 권장 노트 구조

```markdown
---
tags:
  - ncloud
  - lecture-note
source_type: audio-transcript
transcription_status: reviewed-partial
content_qa: reviewed-partial
delivery_readiness: ready-with-limitations
---

# 제목

> [!info] 전사·검수 상태
> 원본 수, 사용 엔진, 실제로 청취한 범위, 합본 링크 또는 경로, `content_qa_status`, `delivery_readiness`를 기록한다.

## 대분류

- [[#분류 A]]
- [[#분류 B]]

## 핵심 요약

## 분류 A

### 핵심 개념
### 세부 설명
### 실습 및 명령
### 질문과 답변
### 주의 및 정정

## 복습 체크리스트

## 전사 불확실성 및 확인 필요

## 출처
```

기존 노트의 구조가 명확하면 그 구조를 우선하고 필요한 절만 추가한다.

`delivery_readiness`가 `draft-only` 또는 `blocked`이면 노트 상단에 최종 확정본이 아니라는 경고 callout을 둔다. 대체 ASR이나 파형 분석만 수행한 경우 이를 오디오 대조로 표현하지 않는다.

## 내용의 출처를 구분한다

- 강의 발화: 단정형으로 정리할 수 있지만 강의 당시 설명이라는 맥락을 유지한다.
- 전사 불확실: `[전사 불확실]` 또는 callout으로 표시하고 추측을 피한다.
- 편집자 해설: 강의에서 직접 말하지 않은 설명임을 밝힌다.
- 최신 공식 확인: 출처 링크와 확인일을 적는다. 강의 당시 설명을 삭제하지 말고 차이를 정정 블록에 둔다.

예시:

```markdown
> [!warning] 강의 내용과 현재 문서의 차이
> 강의에서는 A로 설명했지만, 2026-09-02에 확인한 공식 문서는 B로 안내한다.
> 강의 당시 설명은 학습 맥락을 위해 보존한다.
```

## 코드와 명령

- 들리는 내용을 그대로 복원했는지 확인한 뒤 코드 펜스에 넣는다.
- `$`, 백틱, 따옴표, 대시, 슬래시가 빠지지 않았는지 원본 화면이나 실습 자료와 대조한다.
- 실행해 보지 않았다면 `검증됨`이라고 표시하지 않는다.
- 자격 증명과 토큰은 `<REDACTED>` 또는 환경 변수 자리표시자로 바꾼다.

## 링크와 첨부

- vault 안 문서는 가능하면 기존 위키링크 표기 관례를 따른다.
- 노트 이름이 중복되면 상대 경로를 포함한 위키링크를 사용한다.
- 기존 임베드 `![[...]]`와 callout을 보존한다.
- 새 외부 링크는 실제로 확인한 URL만 넣는다. 확인하지 않은 링크를 그럴듯하게 만들지 않는다.

## 민감정보

다음 항목은 강의 중 들렸더라도 노트에 그대로 기록하지 않는다.

- 비밀번호, API 키, 접근 키, 시크릿, 세션 토큰, Authorization 헤더
- 개인 전화번호, 이메일, 계정 ID처럼 학습에 불필요한 식별자
- 공개하면 안 되는 내부 호스트명, 사설 저장소 주소, 고객 데이터

IP, 포트, CIDR은 실습 개념상 필요할 수 있으므로 무조건 삭제하지 않는다. 실제 운영 식별자인지 예제 값인지 판단하고, 불필요하면 예시 주소로 바꾸되 변경 사실을 기록한다.

## 편집 후 검증

- frontmatter가 시작과 끝 구분선을 모두 갖는지 확인한다.
- 코드 펜스 수가 짝수인지 확인한다.
- `## 대분류`와 각 링크 대상 제목이 실제로 있는지 확인한다.
- vault 루트를 기준으로 새 위키링크가 해석되는지 점검한다.
- 합본에서 다룬 각 대분류가 노트에 반영되었는지 확인한다.
- 노트의 `transcription_status`, `content_qa`, `delivery_readiness`가 납품 검증 보고서와 일치하는지 확인한다.
- 기존 수기 문장과 링크가 의도치 않게 사라지지 않았는지 diff로 확인한다.
- 비밀정보 패턴과 불필요한 개인 식별자가 남지 않았는지 검사한다.
