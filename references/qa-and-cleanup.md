# 전사 QA와 안전한 정제

## 상태 정의

- `machine-audited`: 구조, 시간축, 반복, 신뢰도 메트릭 등 자동 검사만 수행했다.
- `acknowledged-unverified`: 후보에 결정은 기록했지만 직접 청취나 권위 있는 자료로 확인하지 않았다. 감사 플래그는 해결되지 않은 상태다.
- `evidence-reviewed`: 결정이 직접 청취 또는 출처를 기록한 권위 있는 자료에 근거한다.
- `reviewed-partial`: 의심 구간 또는 표본을 실제 오디오와 대조했다.
- `reviewed`: 전체 범위를 실제 오디오와 대조했다.

자동 검사는 오디오 대조를 대신하지 않는다. 엔진이 confidence를 제공하지 않았다는 사실도 낮은 품질이나 높은 품질의 증거가 아니다.

결정 레코드의 존재와 검수 완료를 구분한다. 근거 없는 `keep`은 이후 검토를 위한 메모일 뿐 해당 후보를 해결하지 않는다.

## 우선 검토 구간

1. 시작, 중간, 끝의 대표 구간
2. 20초 이상 긴 무음 뒤 첫 발화
3. 동일하거나 거의 동일한 문장이 연속 반복된 구간
4. `no_speech_prob`가 높고 `avg_logprob`가 낮은 구간
5. compression ratio가 비정상적으로 높은 구간
6. 엔진 특유의 자막, 구독, 감사 문구처럼 보이는 구간
7. 강의 흐름과 무관한 언어 전환 또는 갑작스러운 문체 변화
8. 제품명, 인명, 서비스명, 명령어, 파일 경로, 숫자, 날짜, 금액, 포트, IP/CIDR
9. 질문과 답변의 경계, 실습 실패, 정정, 예외 설명

임계값은 검토 후보를 찾는 출발점일 뿐 삭제 규칙이 아니다. `transcript_ops.py audit`의 플래그에는 근거와 세그먼트 ID가 포함된다.

## 무음 환각 처리

다음 문구가 보인다는 이유만으로 삭제하지 않는다.

- 시청, 구독, 좋아요, 자막 제공 관련 상투 문구
- 같은 문장의 여러 차례 반복
- 녹음 주제와 무관해 보이는 짧은 문장

먼저 원시 출력, 앞뒤 세그먼트, 타임스탬프, 무음 길이, confidence 계열 메트릭을 확인한다. 가능하면 해당 오디오를 직접 듣는다. 실제 발화가 없다고 확인된 뒤 결정 파일에 `exclude`와 이유를 기록한다.

대체 ASR이 문장 형태의 발화를 만들거나 파형에 지속 신호가 있으면 기존 환각 판단과 충돌하는 증거다. 대체 결과를 정답으로 자동 채택하지 말고 `alternate-asr` 근거로 기록한 뒤 직접 청취 전까지 삭제를 보류한다.

## 결정 근거

결정별 `evidence.type`은 다음 중 하나다.

- `audio-listen`: 원본 오디오를 직접 재생해 확인했다. 해당 세그먼트 전체를 포함하는 `source_start`, `source_end`가 필요하다.
- `authoritative-material`: 강의 슬라이드, 공식 공지, 제공된 원고 등 권위 있는 자료로 확인했다. 파일이나 URL을 `reference`에 기록한다.
- `alternate-asr`: 다른 엔진·모델·설정의 재디코딩 결과다. 후보 생성과 충돌 탐지에만 사용한다.
- `machine-metric`: confidence, log probability, no-speech probability, compression ratio, 파형 또는 무음 탐지 결과다.
- `context-inference`: 앞뒤 문맥에 따른 추정이다.

허용 기준:

| 행동 | 필수 근거 | 비고 |
|---|---|---|
| `keep` | 없음 | 근거가 없으면 `acknowledged-unverified`로 남고 플래그를 해결하지 않음 |
| `format_text` | 없음 | 공백·문장 끝 부호·동등한 유니코드 표기만 허용하며 그 밖의 문자 순서가 같아야 함 |
| `replace_text` | `audio-listen` 또는 `authoritative-material` | 숫자, 부정, 주체가 바뀌지 않는지 확인 |
| `exclude` | `audio-listen` | 대체 ASR, 파형, 기계 지표만으로는 금지 |
| `set_speaker` | `audio-listen` 또는 `authoritative-material` | 목소리만으로 신원을 추측하지 않음 |

`reviewed_against_audio=true`이면 다음을 모두 기록한다.

- `audio_review.method: direct-listen`
- 실제로 들은 `reviewed_ranges`
- 각 범위의 `start`, `end`, 검토 이유
- `scope=full`일 때 `coverage_confirmed: true`; 기록한 범위가 타임스탬프가 있는 모든 canonical 세그먼트를 덮어야 함

파형 분석, 무음 탐지, 대체 ASR 비교만 수행했다면 `reviewed_against_audio=false`다.

`format_text`는 일반 문장 정리에만 사용한다. 명령어, 코드, 파일 경로, 버전, IP 주소, 식별자는 공백과 문장부호도 의미가 있으므로 원본 화면, 자료 또는 오디오 근거가 있는 `replace_text`를 사용한다.

## 정제 규칙

- 의미 없는 필러 제거는 요약 노트에서는 가능하지만 검토 전사에서는 기본적으로 보존한다.
- 문장부호와 띄어쓰기를 다듬을 수 있으나 의미, 부정, 수치, 주체를 바꾸지 않는다.
- 불명확한 고유명사나 숫자는 추측하지 않고 `[불명확: …]`처럼 표시한다.
- 겹친 청크의 중복은 시간 겹침과 음성을 함께 확인한 후 한쪽만 제외한다.
- 전사 오류와 강사의 말실수를 구분한다. 강사가 잘못 말한 것이 확인되면 전사는 발화대로 보존하고 Obsidian의 정정 블록에서 설명한다.
- 화자 이름을 목소리만으로 추측하지 않는다. `강사`, `학생 1`, `화자 미상` 같은 최소 라벨도 diarization 또는 직접 대조 근거가 있어야 한다.

## 인코딩과 손상 판단

UTF-8로 정상 해석되는지, `U+FFFD` 대체 문자가 있는지, 원시 바이트가 손상됐는지는 별개의 문제다. 대체 문자가 보인다는 이유만으로 원본 인코딩 오류라고 단정하지 않는다. 공급자 응답, 디코딩 과정, 렌더러를 각각 확인한다.

## 표본 검수 최소선

전체 대조가 현실적으로 어렵다면 적어도 다음 표본을 듣고 `reviewed-partial`로 표시한다.

- 각 파일의 첫 60초와 마지막 60초
- 각 파일 중간의 연속 60초
- 감사 도구가 플래그한 모든 심각 오류 구간
- 고유명사, 숫자, 명령어가 집중된 구간
- 청크 경계 전후 구간

표본 비율과 검토하지 못한 범위를 최종 보고에 적는다.

`reviewed-partial`은 위 범위를 모두 들었다는 뜻이 아니다. 실제 `reviewed_ranges`만 검수된 것으로 보고하며, 검토하지 않은 범위는 확정적으로 교정하거나 삭제하지 않는다.

## 납품 모드

- `draft`: 오디오 대조 전의 비파괴 원시 전사와 Obsidian 초안을 점검한다. 미검수 상태를 허용하지만 근거 없는 삭제·교체·화자 지정은 허용하지 않는다.
- `final`: `reviewed` 또는 `reviewed-partial` canonical만 허용한다. 부분 검수이면 미검수 범위를 최종 보고에 명시한다.

최종 보고에서 구조 검증과 내용 QA를 분리한다.

- `artifact_integrity_status`: 해시, 파일, JSON 구조, 시간축, 합본, Obsidian 구문
- `content_qa_status`: 오디오 대조와 결정 근거 상태
- `delivery_readiness`: `final-ready`, `ready-with-limitations`, `draft-only`, `blocked`

## 중단 조건

다음 경우 전체 합본이나 Obsidian 확정 편집을 멈추고 문제를 보고한다.

- 원본 해시가 작업 중 바뀜
- 파일 순서를 신뢰할 수 없음
- 여러 엔진 결과가 섞였지만 경계를 복원할 수 없음
- 타임스탬프가 소스 길이를 크게 초과하거나 역행함
- 전사 결과가 대부분 반복되거나 무의미한 문구이고 재실행 대안이 없음
- 외부 업로드가 필요하지만 허가가 없음
- 기존 노트의 수기 내용과 자동 생성 영역을 안전하게 구분할 수 없음

안전한 부분 산출물은 보존하고, 완료되지 않은 단계를 명확히 표시한다.
